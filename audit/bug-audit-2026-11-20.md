# Website Bug Audit — 2026-11-20

Full-stack audit of the Techsteal site (Next.js 16.4.6 · React 19.3 · Drizzle
0.45 over Supabase · Vercel Node 24). Read-only code review of every page,
all 39 API route handlers, all `src/lib` modules, every component, infra
config, scripts, and docs; plus a live dev-server smoke/concurrency run and a
production-endpoint probe. Findings below are the ones that survived
verification; the accepted-state list in `AGENTS.md` was excluded on purpose.

Baseline before changes: `tsc --noEmit` clean · eslint **45 warnings / 0
errors** · production build clean · `npm audit` 11 moderate (dev chain).

---

## CRITICAL

### C1 — Intermittent 60-90 s hangs on every DB-backed route (fixed)
`src/lib/db.ts` · **Confirmed in production** (`www.techsteal.space/api/stats`
and `/api/search` timed out during the audit) and reproduced deterministically
outside the app.

`postgres.js` pipelines extra queries onto a connection that already has one in
flight whenever all pooled connections are busy. Supabase's **transaction
pooler (port 6543) never answers a pipelined query** — the bytes go out, no
response comes back, and the handler hangs until an upstream timeout. Repro
with the app's exact pool config: `max: 3` + 4 concurrent queries hangs on the
second round forever; the same queries with `max: 10` or through the session
pooler (5432, which caps the project at ~15 sessions and caused the old
`EMAXCONNSESSION` outages) are clean. Any page whose API fans out into ≥2
parallel queries could stall; more concurrent visitors made it frequent.

Fix: a per-process counting gate (`POOL_MAX` = pool size) in `src/lib/db.ts`
wraps the postgres client so at most 3 statements/transactions are on the wire
at once — a free connection always exists, so pipelining never happens, and
queries still run in parallel (not one global lock). Transactions reserve a
slot for their whole life and are verified not to deadlock against the gate
(direct + nested savepoint transactions tested against the live DB). Verified
through the app: 12 concurrent requests × 6 DB endpoints × 4 rounds → 0
failures, max 2.8 s, typical 0.3-2 s (previously multi-minute hangs).

## HIGH

### H1 — Admin "delete comment" destroyed the whole gallery post (fixed)
`src/components/ModerationPanel.tsx` · `DELETE /api/gallery/[id]` reads
`commentId` from the JSON body and treats an **absent** `commentId` as "delete
the post". The Moderation Hub sent `?commentId=` in the query string with no
body, so confirming "Delete comment by X?" silently destroyed the build, all
of its comments, and its stored images. Same class of bug made thread/reply
deletion from Moderation Hub always answer 400 (ids in query string, handlers
read bodies). All three calls now send the documented JSON bodies.

### H2 — `npm run db:seed` could wipe the live community (fixed)
`drizzle/seed.ts` unconditionally deleted every forum/gallery/poll/timeline/
rules row. It now counts content first, refuses with a per-table report unless
`--force` / `SEED_FORCE=1`, and only clears when the operator explicitly opts
in. Documented in README/AGENTS.

### H3 — `announcements` had no migration (fixed)
An API shipped in the previous pass queried a table absent from every
migration/snapshot, and `drizzle/README.md` told fresh DBs to apply only 0000.
Generated `drizzle/0003_cute_sunset_bain.sql` (+ snapshot/journal) containing
exactly `announcements` and its index; fresh-DB instructions now apply
0000-0003 in order.

## MEDIUM

- **Chatty transcript corruption** — deleting the active conversation while a
  reply streamed swapped `messages`/`activeId` without aborting the stream; the
  next tokens appended the reply into the *other* chat and the throttled save
  persisted it. Delete now calls `stopStreaming()` first (`Chatty.tsx`).
- **Chatty Regenerate/Retry dropped pasted images** — an image-only prompt was
  re-asked as bare placeholder text. Both paths now resend the attachment.
- **Chat images exceeded the request cap** — server accepted 2 × 3 MB data
  URLs (~6 MB JSON) against Vercel's 4.5 MB body limit, so oversized chat POSTs
  failed opaquely. Server now caps per image (2 M chars) and total (3 M), and
  the composer compresses/downscales with the shared `compressImage()` helper
  (≤1.4 MB) before base64-encoding.
- **AI empty-completion swallowed** — a clean-but-empty upstream stream ended
  the reply wordlessly and never tried the fallback model. It now counts as a
  failed round so the model cascade retries; all-models-failed still emits the
  friendly error line.
- **DB outage read as "member not found"** — `getPublicProfile` caught every
  error and returned `null`, making `/api/members/[id]`'s 503 branch dead and
  a pooler outage a 404. Query failures now rethrow → API 503 / page error
  boundary; only genuinely missing/banned/no-MC rows are 404.
- **Moderation/RichEditor/ServerPanel races** — queued editor embeds lost all
  but the last upload; a slow player-list response could render under the wrong
  Server Ops tab (and delete from the wrong list); the 3.5 s refresh used a
  stale list. All three now sequence/guard correctly. NotificationBell now
  checks `res.ok` on mark-read instead of silently leaving a stuck badge.
- **Anonymous reads were unbounded** — `/api/gallery` returned every row plus
  an unbounded comment GROUP BY with no rate limit. Now IP-rate-limited
  (60/min) and capped at 500 rows.
- **Soft 404 / SEO** — `/forum/<garbage>` rendered thread metadata with HTTP
  200 (now strict digits-only `parseRouteId` → 404); dynamic forum/member pages
  dropped the layout's OG image/siteName and had no canonical URL (now set);
  `/gallery?item=` canonicalizes to `/gallery`; sitemap listed profiles with an
  empty Minecraft name that 404 (filter mirrored from the profile query).
- **Wordmark clipped on 320-355 px phones** — the 52 px clamp floor made
  "TECHSTEAL" ~315 px wide in a 280 px slot. Floor is 34 px; desktop unchanged.

## LOW (fixed)

- Literal `null` JSON bodies returned 500 in 7 handlers — all body reads are
  now `?? {}` (verified: malformed bodies get 401/400, never 500).
- `23505` unique-violation branch in `PATCH /api/profile` was dead under
  Drizzle 0.45 (code lives on `err.cause.code`) → concurrent MC-name claims
  answered 503 instead of 409.
- `share_logs` (uploads the server log to mclo.gs) was the only Server Ops
  action missing from the audit trail — added `server_share_logs` verb + call.
- Like notifications had no dedupe: unlike/re-like spammed one row per toggle.
  24 h dedupe on recipient+actor+type+target (best-effort; reply/mention never
  deduped).
- Storage GC compared percent-encoded URL tails against raw bucket keys, so a
  live legacy object with an encoded name could be deleted by the orphan
  cleaner. Paths are normalized to raw keys and the reference scan matches both
  spellings.
- `getLiveStatus` cache window started at request time, so a slow dual-upstream
  fetch could spawn a duplicate fetch; the window now starts when the promise
  settles.
- Chat route lacked `dynamic = "force-dynamic"`.
- `global-error.tsx` lost the brand font; dead CSS (~80 lines: removed
  `.chat-*`, `.btn-discord`, `.reveal*` and three unused glow tokens, all
  grep-proven unreferenced).
- Status tab `aria-controls` pointed at unmounted panels.
- Dev tooling: `scripts/session-proxy.mjs` hardcoded a signed **admin** JWT for
  a real Discord id + a literal secret and listened on `0.0.0.0`; it now
  derives the secret from env, uses a throwaway identity, binds loopback, and
  `dev-harness.mjs` generates a random per-run secret. `apply-vercel-env.mjs`
  now sends the team scope (`teamId` from `.vercel/project.json`) and fails
  fast instead of silently deploying with stale env. Obsolete
  `add-seasons.ts` / `season-six-live.ts` (hardcoded seasons, destructive
  delete) removed — the admin Timeline CMS covers both.
- Dependencies: `npm update` (in-range patches; lockfile refreshed) +
  `npm audit fix` cleared the minimatch/@typescript-eslint advisories
  (11 → 4 moderate, all the accepted dev-only esbuild chain). Added
  `engines`/`packageManager`.

## Not fixed (verified, deliberate)

- `applyDiscordVerification(false)` removes capability bits that may have been
  granted manually. Verification and manual grants share one `permissions`
  column, so the server cannot tell them apart; fixing it needs a schema
  column. Verification is documented as the live source of truth; admin
  overrides can be re-granted. Left as designed, noted here.
- Prompt-injection hardening of model context (member post text / web results
  are untrusted input to the assistant). Real but design-level: mitigations
  need content delimiting + evaluation, not a one-line fix.
- CSP keeps `script-src 'unsafe-inline'` (needed by the palette bootstrap) and
  `img-src https:`. Nothing external is loaded today; nonce work is a
  follow-up, not a launch blocker.
- Per-instance in-memory rate limits/view counts (accepted, see AGENTS.md).
- Design-token consistency on assistant/status surfaces (fixed olive accents
  under every palette) — deliberate-looking branding, left alone.
